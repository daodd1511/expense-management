# Polish — Plan

Third of three sibling specs from the "all Fixes + Features 7–13" batch. Builds on
**Spec 1 (`foundation`)** (facade gone, feature hooks direct, F2 atomic RPC exists) and is
independent of **Spec 2 (`feature-ux`)**. **Does not start until the prior in-flight spec is
merged** (one spec in flight). EXECUTION.md generated by `spec-plan` at activation.

## Scope

Backlog **Feat11, Feat12, Feat13**.

| Item                                    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Feat11** subscription confirm-payment | Today logging is a **raw one-tap** (no confirm, no preview) on both the due banner and the subscription list. Replace it **everywhere** with a **confirmation dialog/sheet** previewing the transaction to be created (amount, account, category, date) + a Confirm action, reusing **F2's atomic `log_subscription` RPC**. The Confirm button carries the loading state (unifies with Feat12).                                                                                        |
| **Feat12** loading states (non-form)    | Forms already covered via `useFormSubmit`. Remaining: (a) **list skeletons** on initial load for the primary data screens (transactions, dashboard, accounts, budgets, subscriptions, categories) driven by each feature query's `isPending`; (b) **delete-confirm** dialogs (CategoryForm delete, subscription/account/transaction delete) get disable+spinner on the confirm button while the mutation runs; (c) the subscription log action's loading is the Feat11 Confirm button. |
| **Feat13** shortcuts + command palette  | **Desktop only** (mobile has tab nav + FAB). Command palette on **Cmd/Ctrl+K**, built on the existing **`@base-ui` Dialog** + a small filterable list — **no new dependency**. Global shortcuts: `N` = new transaction, `/` = focus search. Palette entries: navigate to each screen (Dashboard/Transactions/Accounts/Budgets/Subscriptions/Categories/Settings) + "new transaction/account/budget/subscription". Shortcuts are ignored while typing in an input/textarea.             |

## Provisional phases (finalized by spec-plan at activation)

1. **Subscription confirm-payment** (Feat11) — a reusable confirm dialog previewing the tx;
   wire it into `SubscriptionDueBanner` + `MobileSubscriptions`/`DesktopSubscriptions`,
   replacing the raw one-tap; Confirm button loading state.
2. **Loading states** (Feat12) — list skeleton components + `isPending` wiring across the
   six data screens; disable+spinner on all delete-confirm buttons.
3. **Shortcuts + command palette** (Feat13) — a desktop keyboard-shortcut hook (guarded
   against input focus), the `@base-ui` command palette, and the action/navigation registry.

## Affected files (indicative)

- Feat11: `features/subscriptions/components/{SubscriptionDueBanner,MobileSubscriptions,DesktopSubscriptions}.tsx`,
  a new confirm-payment dialog, `features/subscriptions/queries.ts` (log mutation `isPending`).
- Feat12: new skeleton component(s) in `shared/components/`; the six feature list components +
  their `queries.ts` `isPending`; `features/categories/components/CategoryForm.tsx` delete
  (capture its dropped `isSubmitting`), delete-confirm sites.
- Feat13: new `shared/hooks/useKeyboardShortcuts.ts` + a `CommandPalette` component
  (`shared/components/`), mounted in `layouts/desktop/DesktopApp.tsx`; action registry wiring
  into the new-entity flows and screen navigation.

## Constraints

- Integration branch `develop`; stacked phases. Frontend via `react-frontend-developer`;
  `terse-commit` before commits.
- i18n parity for all new strings (confirm-dialog copy, palette labels, shortcut hints).
- No new dependency for the palette (build on `@base-ui`).
- Reuse F2's `log_subscription` RPC for Feat11 — do not add a second logging path.

## Non-goals

- Off-cycle / early subscription payments (would need a `next_due_date` rule) — not in Feat11.
- Mobile command palette / mobile shortcuts (desktop only).
- Global loading/route-transition spinners beyond the enumerated action + list surfaces.

## Open items

- Exact skeleton visual (shimmer vs. static muted blocks) — resolve at spec-plan/impl time
  against the design tokens; inconsequential to phase structure.
