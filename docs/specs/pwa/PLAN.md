# PWA Plan

Produced via `/grill-me` interview. All decisions below were explicitly confirmed; do not
reinterpret or expand scope without re-confirming.

## Motivation

`vite-plugin-pwa` is wired up (`packages/web/vite.config.ts`) — manifest generated, service
worker registers, `autoUpdate` works, app-shell precached (5 entries, ~1.28MB). But it isn't
actually a working installable PWA yet:

- `manifest.webmanifest`'s `icons` array is empty (`vite.config.ts:24`) — Chrome's
  installability check requires valid manifest icons; without them the install
  prompt/"Add to Home Screen" won't reliably fire.
- No icon in `public/` is a real app-icon candidate: only 32×32 favicons and a 180×180
  apple-touch source exist, nothing at 192/512.
- `index.html` has **zero** favicon tags at all (`<link rel="icon">`, apple-touch-icon) —
  browsers show a blank tab icon. Separate bug, same root cause category, folded into this
  spec.
- `manifest.webmanifest`'s `theme_color`/`background_color` use `oklch(...)` strings —
  manifest parsers (splash screen, status-bar tint) have less consistent CSS Color 4 support
  than page-level CSS; this degrades silently rather than erroring.
- Offline behavior beyond app-shell precache is unhandled — a failed fetch while offline
  currently reads as a generic error, not "you're offline."

## Decisions

| Decision | Choice | Reason |
|---|---|---|
| Icon generation tooling | `@vite-pwa/assets-generator`, integrated via `vite-plugin-pwa`'s built-in `pwaAssets` config option (supported in the installed `v1.3.0`) — no separate CLI script, generation happens as part of the Vite build | Purpose-built companion tool for exactly this gap; avoids manual re-generation every time the icon changes |
| App icon design | New fixed-color source SVG: deep-ink (`--deep-ink`, `oklch(0.18 0.012 80)`) background, mark rendered in Register Gold (`oklch(0.60 0.15 78)`), same mark geometry as `public/icon.svg` | A static install icon can't respond to `prefers-color-scheme` like the existing adaptive `icon.svg` does; gold-on-ink matches DESIGN.md's "ink stamp" brand language and stands out among other apps' icons instead of reading as a placeholder |
| Favicon vs. app icon source | Two separate sources: existing adaptive `public/icon.svg` (light/dark via media query) stays the **favicon** source since browser tabs do respect that query live; the new gold-on-ink fixed SVG is the **install icon / app-icon** source | Different rendering contexts have different capabilities — no reason to compromise the favicon's existing light/dark behavior for the sake of the static install icon |
| Maskable icon safe zone | Handled automatically via the generator's built-in maskable padding preset — full-bleed source used for `purpose: any`, auto-padded version for `purpose: maskable` | Mechanical resizing exactly the tool exists to handle; no manual redraw needed |
| Offline scope | App-shell installability + graceful offline messaging only (banner/state when a fetch fails offline) — **no** offline write queue | App is documented as online-only in `CLAUDE.md`; a write queue is a substantial standalone architectural change (conflict handling, replay-on-reconnect) deserving its own `/grill-me`, not folded into "make it installable" |
| Update UX | Keep silent `autoUpdate` (no "new version — reload" toast) | Simpler, matches the app's low-friction "quiet ledger" philosophy; can revisit once `sonner` lands from the `error-handling` spec if desired later — **superseded by `docs/specs/pwa-update-prompt/PLAN.md`** (switched to `prompt` mode + Settings update control) |
| Manifest theme/background color format | Convert `theme_color`/`background_color` to hex equivalents of the same OKLCH values, scoped only to the manifest config in `vite.config.ts` | Manifest is the one place under-parsing silently degrades UX (wrong splash color) rather than erroring; rest of the design system stays OKLCH-native, this is a narrow mechanical exception |
| Favicon fix | Folded into this spec (was going to need reopening for a two-line fix otherwise) | Same tool run, same root-cause category as the app-icon gap |

## Frontend Changes

### Icon generation

- New `packages/web/src/assets/app-icon.svg` (or similar) — the gold-on-ink fixed-color
  source, same mark geometry as `public/icon.svg`, background `#<hex of deep-ink>`, mark fill
  `#<hex of register-gold>`.
- `packages/web/vite.config.ts`: `VitePWA({ ..., pwaAssets: { image: 'src/assets/app-icon.svg', ... } })`
  configured to emit the standard manifest icon set (192, 512, maskable) plus favicon/
  apple-touch-icon outputs. Existing `public/icon.svg` remains referenced directly for the
  live favicon (light/dark via media query) — not generated by the tool, since the tool's
  output is the fixed-color app icon set.
- `manifest.icons` populated from the generator's output (mechanical — exact array shape
  depends on the generator's manifest-preset output, filled in at implementation time).

### Manifest colors

- `vite.config.ts` manifest block: `theme_color`/`background_color` changed from
  `oklch(0.985 0.004 90)` to the equivalent hex value.

### Favicon + apple-touch-icon wiring

- `packages/web/index.html`: add `<link rel="icon" href="/icon.svg" type="image/svg+xml">`
  (existing adaptive favicon) plus whatever additional `<link>` tags the generator's output
  requires (apple-touch-icon, etc. — generator can auto-inject these via its Vite plugin
  integration, or they're added manually if not).

### Offline messaging

- Graceful offline state: when a fetch fails specifically due to being offline (as opposed to
  a genuine API/server error), show a distinct message rather than the generic error path —
  exact mechanism (browser `navigator.onLine` + `online`/`offline` event listeners vs.
  detecting a network-level fetch failure) is an implementation-time choice, not a design
  decision requiring confirmation.
- No write queue, no retry-on-reconnect — reads only get a friendlier "you're offline"
  treatment; writes attempted while offline fail with the same offline messaging, no special
  queuing behavior.

---

## Explicitly Out of Scope

- Offline write queue / mutation replay on reconnect
- "New version available" update-prompt UX (kept silent `autoUpdate`)
- Redesigning the mark/logo geometry itself — only the color treatment is new
- Changing the existing favicon's light/dark adaptive behavior

## Open Items for Implementation Time

- Exact hex conversion values for deep-ink/register-gold and for the manifest
  theme_color/background_color OKLCH→hex conversion — mechanical, computed during execution.
- Exact `pwaAssets` config shape (which presets/sizes to request from
  `@vite-pwa/assets-generator`) — follow the tool's documented minimal-recommended preset
  (typically covers 192/512/maskable/apple-touch/favicon) rather than hand-picking sizes.
- Exact mechanism for offline detection (event listeners vs. fetch-failure inference) —
  doesn't change user-facing behavior either way.
