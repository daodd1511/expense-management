# Feature UX — Plan

Second of three sibling specs from the "all Fixes + Features 7–13" batch. Builds on
**Spec 1 (`foundation`)** — assumes the facade is gone, selectors live in `shared`, date
utils exist, and `computeBalance` is a shared pure fn. **Does not start until `foundation`
is merged** (one spec in flight). EXECUTION.md is generated by `spec-plan` at activation,
because the checklists reference `foundation`'s merged shape.

## Scope

Backlog **F4, F9** + **Feat7, Feat8, Feat9, Feat10**, plus the server-balance cluster
deferred out of `foundation`.

| Item                                           | Decision                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Balance cluster** (deferred from foundation) | `/api/accounts` returns a computed `balance` field, via the **shared TS reducer** (`computeBalance`, relocated in foundation) called in the route after fetching the user's tx. FE account cards consume `balance` and stop reducing the full tx array. Unblocks F4.                                                                                                                                                             |
| **F4** month-scoping                           | `useTransactions(month)` uses the API's existing `?month=` (default = local current month via `todayLocalIso`). FE no longer fetches all tx. Requires the month switcher (Feat8) to avoid a history regression.                                                                                                                                                                                                                  |
| **Feat8** filter                               | Month switcher (prev/next header) sets the fetched month. Within that set, **client-side** filters: type (exists) + text (exists) + **new category + account**. Unify desktop to match mobile. Amount-range + cross-month custom ranges → backlog.                                                                                                                                                                               |
| **Feat7** analytics                            | Kill the `monthlyTrend` seed: `TrendChart` fed by a new **`GET /api/analytics/monthly-totals`** server aggregate (income/expense per month). Category donut becomes **tappable → drill-down** to the transaction list filtered by that category + month (targets Feat8's category filter). Stays on the dashboard. YoY / custom ranges / dedicated Reports screen → backlog #1.                                                  |
| **Feat9 + F9** category picker                 | Transaction-form favorites picker: render favorites as a **compact tile grid** (icon above, label below) instead of full-width rows. Selected favorite → **tile highlights**. Selecting a **non-favorite** (via "show all") → render it in the **current full-width row style** as the selected indicator (it has no tile). "Show all" modal keeps its grouped list. This replaces the awkward `buildFavoritesList` append (F9). |
| **Feat10** icons                               | Root cause: only 10 icons, **duplicated** across `CategoryIcon`'s `ICONS` resolver and `CategoryForm`'s `ICON_OPTIONS`. Consolidate into **one shared icon registry** (single source of truth) and **expand to ~30–50 lucide icons** (food, coffee, transport, home, bills, fun, health, shopping, salary, gifts, pets, travel, education, …). Picker + resolver both read the registry.                                         |
| **Colors** (added)                             | `CategoryForm`'s `COLOR_OPTIONS` exposes only `chart-1..5` (+ income/expense), but `globals.css` already defines `--chart-1..12` (light + dark). Expose all 12 in the picker; add more OKLCH tokens beyond 12 if a larger palette is wanted. Sibling of Feat10 — same category-customization phase.                                                                                                                              |

## Provisional phases (finalized by spec-plan at activation)

1. **Server aggregates + balance** — accounts route returns `balance` (shared reducer);
   new `/api/analytics/monthly-totals` endpoint + shared DTO. Backend only.
2. **FE data layer + month scoping** — `useTransactions(selectedMonth)`; account cards
   consume server `balance` (retire client-side card reduction); analytics query hook.
3. **Transactions filters + month switcher** (Feat8 + F4 UI) — month switcher component;
   type/category/account/text filters; unify desktop + mobile.
4. **Dashboard analytics drill-down** (Feat7) — `TrendChart` real data; donut tap →
   Phase-3 filtered list. Depends on Phase 3's category filter.
5. **Category picker tiles + icons + colors** (Feat9/F9 + Feat10 + colors) — tile-grid
   favorites picker, selected-row for non-favorites; consolidated + expanded icon registry;
   expose all 12 chart colors in `COLOR_OPTIONS`. Independent of the data-layer phases.

## Affected files (indicative)

- API: `packages/api/src/routes/accounts.ts`, new `packages/api/src/routes/analytics.ts`,
  `packages/shared/src/dtos/` (analytics + account-balance DTOs).
- Web data: `features/transactions/queries.ts` + `db.ts` (month param),
  `features/accounts/queries.ts` (balance), new `features/dashboard/queries.ts` (analytics).
- Web UI: `features/transactions/components/{DesktopTransactionsTable,MobileTransactions}.tsx`
  (+ new month-switcher + filter components), `features/dashboard/components/{DesktopDashboard,MobileHome}.tsx`
  - `shared/components/Charts.tsx` (donut drill-down), `features/categories/components/{FavoriteCategoryPicker,CategoryPicker}.tsx`,
    `features/categories/components/CategoryForm.tsx`, `shared/components/CategoryIcon.tsx` +
    new `shared/icons.ts` (registry). Remove `monthlyTrend` from `core/data.ts`.

## Constraints

- Integration branch `develop`; stacked phases. Frontend via `react-frontend-developer`;
  `terse-commit` before commits.
- i18n parity for any new strings (filter labels, month switcher, analytics titles).
- Money/aggregate math stays in tested TS (server reducer + analytics aggregation).

## Non-goals (→ backlog)

- Year-over-year, custom date ranges, dedicated Reports screen (backlog #1).
- Amount-range filter, cross-month filtering (server-side filter params).
- Emoji category icons (curated lucide registry only).

## Open items

- Month-switcher placement/interaction on mobile vs desktop — resolve at spec-plan time.
- Whether account `balance` ships as a field on the accounts payload vs a sibling
  `/api/accounts/balances` endpoint — lean toward a field on the payload; confirm at
  spec-plan time against the accounts query shape.
